\chapter*{Preface}
\addcontentsline{toc}{chapter}{Preface}

Welcome to \textbf{Volume V: Software Architecture and Engineering Economics}, the capstone synthesis of the \emph{Modern Engineering Curriculum}.

If you have previously coordinated software projects---writing feature specifications, reviewing pull requests, debugging integrations, or managing cloud deployments---you have already felt the tension between moving quickly and building systems that survive real traffic. Modern tools can generate boilerplate code in seconds, but they cannot decide what guarantees a system must uphold, where security boundaries belong, how much downtime a business can afford, or why a dedicated GPU cluster might quietly cost ten times more than an API endpoint.

\section*{How This Volume Teaches}
Every chapter in Volume V builds from first principles:
\begin{enumerate}[leftmargin=15pt]
  \item \textbf{Problem Before Notation:} We never drop a diagramming standard, threat matrix, or equation cold. We start with a concrete failure---an oversold ticket flash sale, a silent 1.8\% error leak, or an OOM-crashing language model---and derive the engineering tool needed to diagnose and prevent it.
  \item \textbf{No Assumed Specialist Prerequisites:} Whenever a topic touches database locks, TLS, Prometheus counters, Kubernetes cgroups, or Transformer attention, the chapter builds the exact mental model and small numerical trace you need right on the page.
  \item \textbf{Step-by-Step Verification:} Every non-trivial code listing, PromQL rule, DSL model, and cost calculation is walked through line by line on concrete inputs.
\end{enumerate}

\section*{The Nine-Chapter Progression}
The chapters are ordered to mirror how real systems are conceived, verified, governed, and funded:
\begin{itemize}[leftmargin=15pt]
  \item \textbf{Chapter 1: Requirements Engineering} -- Translating vague stakeholder wishes into testable FURPS+ constraints, discrete latency histograms, availability nines, Little's Law concurrency bounds, and RPO/RTO recovery targets.
  \item \textbf{Chapter 2: C4 Architecture Modeling} -- Zooming cleanly across System Context, Containers, Components, and Code, plus Architecture-as-Code with Structurizr DSL.
  \item \textbf{Chapter 3: UML and Sequence Diagrams} -- Tracing time, synchronous vs.\ asynchronous calls, combined fragments, concurrency races, and OAuth 2.0 PKCE flows.
  \item \textbf{Chapter 4: Threat Modeling} -- Drawing Data Flow Diagrams and trust boundaries, applying STRIDE-per-Element, mapping cryptographic mitigations, and automating checks in code.
  \item \textbf{Chapter 5: SLOs, SLIs, and SLAs} -- Building Prometheus counters and \texttt{rate()} mechanics from scratch, formulating valid availability SLIs, deriving error budget burn rates, and replacing noisy alerts.
  \item \textbf{Chapter 6: Architecture Decision Records} -- Preserving architectural rationale in Git with Nygard/MADR records, superseding chains, PostgreSQL RLS pooling rules, and AST fitness tests.
  \item \textbf{Chapter 7: Technical Design Documents} -- Synthesizing Chapters 1--6 in one end-to-end mini-TDD walkthrough, including \texttt{ALTER TABLE} lock safety, Expand-and-Contract migrations, and FMEA.
  \item \textbf{Chapter 8: Cloud FinOps and Engineering Economics} -- Bridging Azure and AWS cost primitives, unit economics, Savings Plan break-even math, Spot resilience, S3/Blob lifecycles, and Kubernetes bin-packing.
  \item \textbf{Chapter 9: AI Inference Economics and Cost Optimization} -- Explaining GPU memory hierarchies, floating-point formats, and Transformer KV caches from first principles before applying the Roofline model, PagedAttention, continuous batching, and realistic utilization break-even math.
\end{itemize}
